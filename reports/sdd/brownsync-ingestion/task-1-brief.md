## Exact interfaces

- `PlaceRow`, `OrganizationRow`, `EventRow`, `CourseMeetingRow`, `SourceRunRow`.
- All inherit a strict Pydantic v2 base with `extra="forbid"`.
- `model_identity(row) -> tuple[str, ...]`.
- `publish_ndjson(rows, model_type, destination, staging_root) -> int`.
- Separate policy functions validate ingestion slugs, coordinates, confidence, and CAB temporal plausibility; policy rules must not make a schema-valid row fail Pydantic construction.

## Exact schema decisions

- List fields use independent default factories.
- Event `id`, `first_seen_at`, and `last_seen_at` are optional so database defaults can be omitted from seed rows.
- SourceRun `id` is optional at schema level; the source-run log assigns monotonic integers in Task 2.
- UTC-normalize timezone-aware event/run datetimes. Reject naive event/run datetimes.
- Course `days` must tokenize in canonical order from `M,T,W,Th,F,S,Su`, consuming `Th` and `Su` before single-character tokens. Reject empty, duplicate, or out-of-order tokens.
- JSON raw values must be recursively JSON-safe.
- Do not add `OrganizationRow.raw`.
- Polygon is `str | None` and, when present, must be plain `MULTIPOLYGON(...)` WKT at the policy layer.
- Contract models do not enforce DB-absent latitude/longitude/confidence/slug/start-before-end checks; policy functions do.
- JSON output uses `model_dump(mode="json", exclude_none=True)`.

## Atomic publisher behavior

- Validate/materialize every input as `model_type` before touching an existing destination.
- Identity is `("id", value)` when a non-null ID exists; an ID-less event uses `("event", source, source_id)`. Reject duplicate identities.
- Sort deterministically by identity.
- Write compact UTF-8 NDJSON with one object per line beneath the supplied `reports/tmp/` staging root.
- Flush and fsync, then call `os.replace`.
- Clean all staging artifacts after success or failure.
- Any validation/write failure leaves an existing destination byte-for-byte unchanged.
- Atomicity claim is per file only.
